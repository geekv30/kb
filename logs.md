## Session learnings (2026-05-12)

Captured here so the next session inherits the corrections rather than re-discovering them.

- **"Complete swap" means visible pixels, not source files.** The initial icon-swap PR was scoped to `apps/demo/src/**` Remix imports only. When the user said "complete swap" they meant every icon visible in the running demo — including the ones rendered by kb-ui internals. Phase 1 left ~50 visible icons as Remix because they were emitted from within `packages/kb-ui/**`. Lesson: when the user uses words like "complete", "everywhere", "all", clarify whether the unit is the file or the pixel before scoping. The pixel interpretation is usually right for UI-fidelity tasks.

- **`Agent` "rejected" results do not guarantee a clean working tree.** When a user interrupts a ui-engineer dispatch, the tool returns `The user doesn't want to proceed with this tool use. The tool use was rejected (eg. if it was a file edit, the new_string was NOT written to the file).` That parenthetical is misleading — the agent may have completed several `Edit` calls before the kill signal arrived. In this session, an interrupted kb-ui dispatch left 12 unauthorized edits on disk. ALWAYS run `git status` immediately after any rejected/interrupted Agent call. Codified as memory `feedback_check_git_status_after_interrupt`.

- **Final-message rule for UI work: always surface a runtime URL.** The user explicitly added this expectation mid-session ("i've always told you to surface a working link after you are done"). A PR link alone is not enough — the localhost URL (`http://localhost:5173/` for Vite demo, `http://localhost:6006/` for Storybook) belongs in the final message of any UI-affecting task, in the same turn. Codified as memory `feedback_surface_working_link`.

- **Vite dev-server caches workspace deps via pre-bundling.** After a kb-ui dist rebuild, the demo's dev server may still serve the previous pre-bundled version. When the user reports "the change isn't visible" after a correct fix lands, the remedy is `rm -rf apps/demo/node_modules/.vite && vite --force` and a hard-refresh in the browser. The HMR log will show `Forced re-optimization of dependencies` when this happens.

- **Storybook keeps its own Vite cache and must be cleared too.** After dropping `@remixicon/react` from kb-ui's deps in PR #66, Storybook still failed to load half the stories with `ENOENT: no such file or directory, open '.../@remixicon/react/index.mjs'`. The cache lives at `packages/kb-ui/node_modules/.cache/` (separate from the demo's `apps/demo/node_modules/.vite`). When a dep is added or removed in kb-ui, clear BOTH caches and restart, not just the demo's.

- **`Table` icon name collides with Tiptap's table extension.** When swapping to `@untitledui/icons`, importing `Table` directly into `ContentEditor.tsx` shadows `Table` from `@tiptap/extension-table`. Always alias the icon (`Table as TableIcon`) when a same-named import already exists in the file.

- **Auto-X behaviors must yield to explicit user actions.** `FileExplorerNav` had `isExpanded = expanded.has(id) || isActiveSub` — the second clause force-expanded any folder that was an ancestor of the active route, overriding `toggleFolder()`. Whenever you add an "auto-X" rule (auto-expand on mount, auto-select on navigate, auto-focus on open), make sure the user's explicit toggle wins. Initial state and route-change effects are the right place for auto-X; the render-time derivation is not.

- **`@untitledui/icons` v0.0.22 has three known gaps.** No 1:1 match for ordered lists (both ordered + unordered use `List`), blockquotes (use `MessageTextSquare02`), or H3 (use `HeadingSquare`). Documented in [project_kb_icons_untitledui_swap](../.claude/projects/-Users-varunkelkar-Desktop-ai-kb/memory/project_kb_icons_untitledui_swap.md). If a future task surfaces this drift again, swap the visual but flag it rather than re-investigating the catalogue.

- **`Modal` primitive is the canonical centered-overlay surface.** Don't hand-build new Radix Dialog chrome — wrap `Modal` from `@test-kb-ui/kb-ui`. As of 2026-05-12, both `ConfirmDialog` and `ShortcutsCheatSheet` use it; the only intentional non-Modal Dialog in the repo is `SideSheet` (side-docked, different intent).

- **Auto-X "additive useEffect" is still a smell when the source set is re-derived every render.** PR #68 removed the render-time `||` variant of the auto-expand anti-pattern from `FileExplorerNav`. PR #70 caught a second face the same day: a `useEffect([autoExpandIds])` that *only added* members back into local state. The set itself was a memoized derivation of `activeId + items`, and the items memo got a new identity on every store dispatch — so the "additive only" effect re-added the active folder on every render, undoing the user's collapse. The corrected pattern: split the auto-X into two parts — (a) **ancestors of active** can re-apply freely on every render (collapsing an ancestor would hide the active row, so we don't honor that), but (b) **the active item itself** is auto-expanded only on `activeId` *identity change*, tracked via `useRef`. After that one-shot add, the user's explicit toggle wins. Refined the [[feedback_auto_behavior_yields_to_user]] memory with this variant.

- **Tailwind v4 preflight no longer ships font-smoothing defaults.** Tailwind v3 set `-webkit-font-smoothing: antialiased` + `-moz-osx-font-smoothing: grayscale` on `html` for free. v4 dropped both. macOS browsers fall back to subpixel AA, which makes Inter render ~0.5-1 weight steps heavier than Figma. Anyone bootstrapping a Tailwind v4 design system that uses Inter (or any sans-serif tuned to greyscale rendering) should add the two rules to the base CSS. Codified as [[feedback_tailwind_v4_font_smoothing]].

- **Vercel monorepo deploys need an explicit workspace-build chain.** `apps/demo` lists `@test-kb-ui/kb-ui: "*"`, which resolves to the npm-workspace symlink — but the package's `exports` field points to `dist/`. `vite build` in `apps/demo` will fail with module-not-found unless kb-ui has been built first. The repo's `vercel.json` chains `npm run kb-ui:build && npm run demo:build` for this reason. If Vercel ever fails with "Cannot find module '@test-kb-ui/kb-ui'" after a clean install, the kb-ui build step is missing or out of order.

- **Vercel Deployment Protection silently 401s shareable URLs.** New Vercel projects on a personal/team scope ship with SSO protection enabled. Only the canonical `<project>-<random-word>.vercel.app` alias is public; every per-deploy `<project>-<hash>-<scope>.vercel.app` URL returns HTTP 401 unless the visitor is logged into the team. Users who paste a per-deploy URL externally hit a broken link. To turn it off project-wide: `PATCH https://api.vercel.com/v9/projects/<projectId>?teamId=<teamId>` with `{"ssoProtection":null}` and the bearer token from `~/Library/Application Support/com.vercel.cli/auth.json`. The CLI has no `vercel project protection` command for this. After the PATCH, both alias and per-deploy URLs return 200.

- **`vercel git connect` needs the Vercel GitHub App installed on the repo first.** `vercel link --yes` creates the project and reads the local `origin` remote, but it cannot install the GitHub App for the user. If the App isn't on the org/repo, `vercel git connect` errors with `Failed to connect <owner>/<repo> to project. Make sure there aren't any typos and that you have access to the repository if it's private.` — a misleading message; the actual fix is a one-time browser flow at https://github.com/apps/vercel/installations/new. There is no CLI way around it. Until done, deploys still work via `vercel --prod` but pushes to `main` won't auto-deploy.

## Session learnings (2026-05-15) — AI Gaps interaction refactor

Shipped a 5-chunk refactor (#83-#87) of the AI Gaps review experience to make all suggestion cards visible from page-load (Y-paired to their article highlights), click-to-activate flow, custom rAF smooth scroll replacing janky `scrollIntoView`, position indicator + remaining counter + terminal state. Then two follow-on fix PRs (#88, #89) caught real defects the chunk-level Playwright passes missed.

- **Sticky containers silently overlap Y-anchored siblings.** The AI Gaps rail summary was `sticky top-4` while paired suggestion cards were absolute-positioned at their highlights' `offsetTop`. First card's anchor at `~50px` landed inside the summary's `~200px` flow space; sticky's `z-[1]` made it cover the card. Initial-load looked broken (image 3) AND every scroll position had partial overlap. The chunk-3/4/5 Playwright passes all framed the summary at top + visible card below it on the FIRST load with the active state — that frame happened to fall outside the broken state, so the tests passed while the bug was live. **Lesson:** when laying out multiple sibling elements with different positioning models (sticky + absolute Y-anchored), the collision walk must seed `prevBottom` from the sticky element's flow bottom, OR drop the sticky entirely so the rail scrolls naturally. PR #88 dropped sticky + seeded the walk with measured summary height + minGap. Codified as memory `feedback_sticky_yields_to_anchored_siblings`.

- **Don't render buttons that look enabled but are disabled.** Idle paired cards rendered Accept/Reject pills per Figma 2829:9484 (which shows them for visual parity) but kb-ui marked them `disabled`. User clicked, got no response, reported "accept doesn't work". The Figma showing controls in the idle variant didn't mean the controls should be inert — it meant they should render and FIRE. PR #88 enabled them with `stopPropagation`-wrapped handlers; card-body click still activates, button clicks act directly (reducer accepts by id regardless of `activeIndex`). **Lesson:** when a Figma variant shows a control, the default reading is "this control is functional in this state". If you intend to render-but-disable, ask the user to confirm. Codified as memory `feedback_no_disabled_lookalikes`.

- **User UI complaint → fetch the Figma source before patching.** When the user said the Settings + AI Suggestions cards in the rail looked "inconsistent," my first move was to propose fixing the border color (the obvious surface diff). The user pushed back: that was patching cosmetics. The actual issue (which only became clear when the user sent the Figma reference) was 4 structural deltas — wrong border token, missing shadow, wrong gap, generic stock copy where context-specific copy was specified. Fixing only the border would have shipped 3 still-broken items. **Lesson:** when the user flags a visual issue without pointing at a specific token, the right first step is to fetch the Figma reference and do a multi-axis side-by-side comparison (border, shadow, padding, radius, gap, copy, hierarchy). Then ask which to fix, not "should I fix the border?" PR #89 shipped all four corrections after the Figma comparison. Codified as memory `feedback_compare_to_figma_before_patching`.

- **Chunk-level "agent verified" reports don't guarantee end-to-end correctness.** All 5 chunk dispatches (PR #83-#87) reported Playwright walks of their respective scope completing cleanly. None of those walks caught the sticky-summary overlap (bug A — visible on load, every scroll position) or the disabled-accept (bug B — user's first click did nothing). Each chunk verified ITS scope; nobody verified the composite end-to-end UX with fresh eyes. **Lesson:** when shipping a multi-chunk refactor of a user-facing flow, dispatch a final end-to-end verification chunk separate from the implementation chunks — OR do a manual eyeball pass yourself before declaring done. Don't trust the cumulative "all chunks green" as proof the flow works.

- **AI Gaps rail architecture (post-refactor) — load-bearing pieces for future work:** `AIGapRail` is the new paired-Y layout primitive (`packages/kb-ui/src/components/content/AIGapRail.tsx`); `useAnchorPositions` measures `data-suggestion-id` offsetTops relative to a container ref; `smoothScrollTo` (`utils/smoothScrollTo.ts`) is the rAF-based scroll utility (respects `prefers-reduced-motion`, cancels on manual scroll); `useAIGapsReducer` has `activateSuggestion(id)` for click-activation and strict-forward `accept`/`reject` auto-advance (no wrap); `AIGapSuggestionCard` has `idle | active | accepted | dismissed` states; `AISuggestionsCard` has `pre-review | reviewing | terminal` modes — pre-review/terminal use `border-surface-muted` + `tokens.shadow.md` to match `ArticleSettingsPanel`. Per-article AI summary lives on `Article.aiGapsSummary` (`apps/demo/src/store/types.ts`).
